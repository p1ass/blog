# 0002. ビルドを外部サービスから切り離す

日付: 2026-09-11

状態: 承認済み

## 背景

ビルドが 3 種類の外部要因に依存していました。

- `blog-api.p1ass.com`: リンクカードの OGP を取得する自前のサービス。Go の `github.com/otiai10/opengraph` を使っていた
- `og-image.p1ass.com`: OG 画像を描く自前のサービス。vercel/og-image のフォーク
- リンク先のサイトそのもの: 55 記事から 196 箇所を、ビルドのたびに取得していた

記事を 1 文字も変えていなくても、このどれかが落ちればデプロイが失敗します。しかも失敗の出方が悪く、`fetchOgp` が例外を投げると `@hono/vite-ssg` がそれを握りつぶし、ページの代わりに "Internal Server Error" を中身とする `index.txt` を書き出します。ビルドは成功したまま、その記事だけが本番から消えます。実際に `java-catch-up` と `line-dev-day-2018` がこの状態で出ていました。

応答の揺れは見た目の回帰テストにも出ます。同じコードに対して、リンクカードの内容が変わるだけで基準画像との比較が落ちたり通ったりしました。

外部サービスは 2 つとも自前のものです。落ちたときに直せるのは自分だけで、しかも落ちていることに気づくのはブログの公開が止まったときでした。

## 決定

ビルドが外部へ出るのを、リンクカードを足した直後だけにします。

**OGP の取得を自前で行い、結果をリポジトリに持ちます。** `app/lib/ogp-fetch.ts` がリンク先の HTML を取り、meta タグから `title`、`description`、`image` の 3 つだけを読みます。取るものが meta タグだけなので、別のサービスを立てて持ち続ける理由がありません。結果は `ogp-cache.json` としてコミットし、更新は `pnpm ogp:refresh` の手動実行にします。ビルドが取りに行くのはキャッシュに無い URL だけです。

**OG 画像をビルド時に生成します。** `scripts/generate-og-images.ts` が satori と resvg で 1 枚ずつ描き、`dist/posts/<slug>/og.png` へ書き出します。記事は 1 年に 10 本ほどしか増えず、タイトルは公開したあと変わりません。1 度生成すれば済むものを、共有されるたびに描くサービスとして持つ理由がありません。

**取得に失敗しても例外は投げません。** タイトルの代わりに URL を出した素のリンクにフォールバックし、記事そのものは出します。例外を投げて記事ごと消すより、カードを 1 つ寂しくするほうがよいという判断です。ビルドの最後に `scripts/check-build-output.ts` が全記事の `index.html` を確かめるので、"Internal Server Error" を書き出していればそこで止まります。

## 検討した案

**キャッシュに TTL を持たせる**: ビルドのたびに生成物の差分が出て、ローカルと CI でキャッシュがずれるため見送りました。

**キャッシュを定期実行で更新する**: PR が増えるだけで、手動のスクリプトで足ります。

**ビルド時の取得をやめる**: キャッシュに無い URL は素のリンクにする案です。ビルドから外部への通信がゼロになりますが、リンクカードを足した直後の確認が `pnpm ogp:refresh` を回すまでできません。カードを足すのは記事を書くときだけなので、そのときの手数を優先しました。

**OG 画像を Playwright の chromium で生成する**: `rehype-mermaid` が既に chromium を入れているため追加の依存はゼロですが、77 枚のスクリーンショットでビルドが伸びるため見送りました。satori と resvg は 68 枚で 1.2 秒です。

**OG 画像をリポジトリにコミットする**: 差分が読めない PNG を 68 枚抱えることになります。生成が 1.2 秒で済むなら、ビルドのたびに作るほうが軽いと判断しました。

## 結果

外部サービス 2 つへの依存が消えました。ビルドが外部へ出るのは、リンクカードを足した直後の 1 回だけです。

`ogp-cache.json` は Go のサービスの応答をそのまま持っていましたが、使うのは 3 つのフィールドだけでした。`title` / `description` / `image` に絞り、既存の 203 件はその場で移してあります。取り直していないので、リンク先がその後に消えたページのカードも残ります。

OG 画像の色は `app/styles/theme.ts` の明るいテーマを参照します。以前はサービス側に `#4172B5` が直接書いてあり、こちらのトークンを変えると 2 つの青がずれる状態でした。

解析は `app/lib/ogp-fetch.test.ts` で見ます。meta タグの読み取りと実体参照と文字コードの判定を、ネットワークへ出ずに検証できます。
