# 0001. 一覧の抜粋をビルド時に export する

日付: 2026-09-06

状態: 承認済み

## 背景

記事の一覧ページには、本文の冒頭を抜粋として載せています。本文中の `{/* <!--more--> */}` より前が抜粋にあたります。

この抜粋は長らく、記事本体とはまったく別の経路で描画されていました。`PostSummarySection` が mdx ファイルを `fs.readFileSync` で文字列として読み、マーカーで切ります。続けて `split('---')[2]` で frontmatter を落とし、それを `MarkdownRenderer` が実行時に MDX としてコンパイルする、という流れです。

この経路には次の問題がありました。

- remark と rehype のプラグインが適用されていない。プラグインを渡すとエラーになるためコメントアウトされていた。結果として一覧ページでは、表・シンタックスハイライト・取り消し線・Mermaid のいずれも効かない
- 画像パスを、コンパイル済みの JavaScript 文字列に対する `replaceAll('./', imgBaseUrl)` という無差別置換で解決していた。本文に `./` が現れれば壊れる
- `split('---')[2]` が本文中の水平線でも切れる。実際に 1 記事の抜粋が冒頭の挨拶までしか出ていなかった
- 一覧ページごとに実行時の MDX コンパイルが 10 本走る

さらに、目次の生成を入れるには見出しの抽出とアンカーの付与が要ります。経路が 2 つあると両方に入れる必要があり、しかも片方はプラグインを受け付けない状態でした。

## 決定

抜粋を、記事本体とまったく同じ経路でビルド時にコンパイルします。

Vite プラグイン `mdx-summary` を追加し、`<slug>/index.mdx` の隣に `<slug>/index.summary.mdx` という仮想モジュールを作ります。中身はマーカーより前だけです。記事本体の側には、この仮想モジュールを `ContentSummary` として再 export する 1 行を足します。

`@mdx-js/rollup` から見れば `index.summary.mdx` は普通の `.mdx` ファイルなので、remark と rehype のプラグインがそのまま効きます。同じディレクトリに置くため、画像の相対パスも記事本体と同じ規則で解決されます。

マーカーが無い記事はビルドを落とします。

## 検討した案

**remark プラグインで mdast を分割する**: 実行時コンパイルのコストと画像パスのワークアラウンドが残るため見送りました。マーカー自体は mdast で `mdxFlowExpression` として見えるので分割は可能ですが、分割した部分木を名前付き export のコンポーネントに変換するには mdast から estree への変換を自前で書く必要があります。

**recma プラグインで分割する**: マーカーの `{/* <!--more--> */}` はコンパイル過程で空の式として消えるため、recma の段階では境界が残っていません。

**抜粋をやめて `description` を出す**: 最も単純ですが、一覧から画像とリンクカードが消えて見た目が変わるため見送りました。

## 結果

`MarkdownRenderer.tsx` を削除し、`PostSummarySection` から `node:fs` と `node:path` への依存が消えました。

一覧ページの抜粋で、表とシンタックスハイライトと取り消し線が効くようになりました。実際に 4 ページで取り消し線の描画が変わり、1 記事の抜粋が本来の長さに戻りました。

ビルド時間は 40 秒から 34 秒になりました (キャッシュを消した状態での計測)。

仮想モジュールという仕掛けを 1 つ抱えることになります。`.mdx` を扱う仕組みを変えるときは、`app/lib/mdx-summary.ts` も一緒に見てください。
