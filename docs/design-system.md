# デザインシステム

## このドキュメントについて

このブログのデザインシステムの仕様と、その構築作業の進捗をまとめています。

新しいセッションを始めるときは、このドキュメントと [CONTEXT.md](../CONTEXT.md) と [CLAUDE.md](../CLAUDE.md) を読んでください。用語の定義は CONTEXT.md、コードの書き方は CLAUDE.md にあります。基盤の改善計画は [refactoring-plan.md](refactoring-plan.md) にあり、そちらのステップ 6 (OGP の内製化) と 7 (ダークモードと TOC) はまだ残っています。

進捗は「作業ステップ」の各見出しにある状態欄で管理します。ステップを終えたら状態を更新してください。

## なぜこの作業をするのか

このブログの見た目は、必要になるたび値を足す形で作られてきました。その結果、同じ役割でも場所ごとに違う値が使われています。

調査した時点で、font-size は 17 種類ありました。`12px` `13px` `14px` `17px` `22px` `0.8rem` `0.85rem` `0.9rem` `1.1rem` `1.2rem` `1.3rem` `1.5rem` `1.5em` `1.75rem` `2rem` `2.5rem` `85%` です。余白は `1.7rem` の倍数と生の値が混ざり、ボーダーは `0.5px` `1px` `0.2rem` `0.25rem` が並立していました。

この状態では、AI が新しいコンポーネントを書くときに参照する基準がありません。既存のコードを真似ても、真似た先の値が正しいとは限らないためです。

そこで値を役割ごとのトークンに寄せ、そこから外れた変更を機械的に検出できるようにします。

## 決定事項

ここに書いた内容は合意済みです。実装中に前提が崩れた場合は、このドキュメントを更新してから進めてください。

### トークン

色は値そのものと役割の 2 層に分けます。`app/styles/palette.ts` が色そのものの名前を持ち、`app/styles/theme.ts` が役割への割り当てを持ちます。コンポーネントから見えるのは `app/styles/color.ts` の役割名だけです。

役割名だけだと、テーマを 2 つ持ったときにダーク側の値を決める基準がなくなります。

色以外はテーマで変わらないので、型付きの TypeScript の定数として持ちます。

| ファイル | 内容 |
| --- | --- |
| `palette.ts` | 色の値そのもの。neutral が 12 段、accent が 10 段。warning と tip だけ別の色相を 4 段ずつ持つ |
| `theme.ts` | 役割への割り当て。テーマを足すときは同じ形の表をもう 1 つ書く |
| `color.ts` | 役割名。`var(--color-*)` を返す |
| `link.ts` | リンクの状態。トークンではないが、下線の引き方を 2 種類に絞ってここへ集約する |
| `typography.ts` | フォントサイズ、行間、フォントウェイト、フォントファミリー |
| `spacing.ts` | スペーシング。4px の倍数 |
| `shape.ts` | 角丸とボーダーの太さ |
| `motion.ts` | モーションの長さとイージング |
| `breakpoint.ts` | ブレークポイントと本文幅 |

### カラー

既存の 11 色を測りました。text が 218 度、textMuted が 215 度、border が 214 度、icon が 216 度、accent が 215 度で、すべて 214〜218 度に収まっています。もともと 1 色相の濃淡でできていたので、それを明示して隙間を埋めただけになっています。既存の値はすべて段のどれかとして残してあります。

accent の 500 は OG 画像の下辺のボーダーにも使っている事実上のブランドカラーなので動かしません。

本文リンクの下線には accent の 400 を `accentMuted` として当てています。300 のほうが「薄い」の見た目には近いのですが、白地で 2.35 対 1 にとどまります。下線はリンクを色以外で見分けるための印なので、UI 部品と同じ 3 対 1 を満たす 400 (3.24 対 1) を採りました。

もともとは色相 215〜216 度の 1 系統だけで組んでいました。`Note` に 3 種別を入れるにあたって、warning (色相 35 度) と tip (色相 145 度) を足しています。同じ色相の濃淡で分けると、記事を流し読みしたときに「いつもと違う」が伝わらないためです。段は `Note` で使う面とアイコンの 2 つだけ置いてあります。

ダークの割り当ては、ライトの段の並びをそのまま裏返して作りました。text は neutral の 900 と 200、surface は 0 と 950 で、地と文字の関係が入れ替わるだけになります。地を neutral の 950 としたとき、本文は neutral の 200 で 14.28 対 1、textMuted は neutral の 400 で 6.40 対 1、accent は accent の 300 で 8.29 対 1 です。3 つとも AA を超えます。

面どうしの差は、ダークのほうがライトより広く出ます。段の刻みが暗い側で粗いためです。surfaceSubtle は地に対してライトが 1.05 対 1、ダークが 1.17 対 1、border はライトが 1.32 対 1、ダークが 1.99 対 1 になります。中間の段を作れば揃えられますが、暗い地では同じ比でも差が見えにくいので、粗いまま使っています。

本文リンクの下線は、ダークでは accent の 500 です。ライトが accent の 1 段薄い色を使うのに対して、ダークは 2 段濃い色を使います。1 段違いの accent の 400 だと 5.85 対 1 あり、リンクの文字 (8.29 対 1) との差が付きません。

accent の 300 だけ、彩度を他の段の 47% ではなく 80% にしてあります。暗い地に置くと同じ彩度でも色みが弱く見え、リンクの青がくすんで感じられたためです。ライト側の段は変えていません。500 は OG 画像のボーダーと同じブランドカラーで、OG 画像は別のサービスが描くので、こちらだけ動かすと 2 つの青がずれます。

warning と tip はダーク用に 300 と 900 の 2 段を足しました。ライトの 50 と 600 に対応します。accent も Note の面のために 900 を足しています。

### タイポグラフィ

フォントサイズは本文 17px を基準に、比 1.2 の等比で組みます。名前は用途で付けます。段の番号にすると「見出しにはどれか」を毎回決め直すことになりますが、用途名なら書くものから引けます。

| 名前 | 値 | 用途 |
| --- | --- | --- |
| `caption` | 13px | 日付やキャプション |
| `bodySmall` | 15px | リンクカードの説明などの補助的な本文 |
| `body` | 17px | 記事の地の文 |
| `h4` | 20px | |
| `h3` | 24px | |
| `h2` | 28px | |
| `h1` | 34px | 記事タイトルとサイト名 |
| `code` | 14px | コードブロック |

行間は本文 1.9、見出し 1.4、1 行で収まるもの 1.25 です。倍率で持ち、px では持ちません。px にすると文字サイズを変えたときに追従しません。

フォントは読者の OS のものを使います。Web フォントを入れないのは表示速度を保つためで、見た目の伸びしろはフォントそのものより行長と行間とサイズの整理のほうが大きいと判断しました。

h5 と h6 は本文と同じ大きさにして太さだけで区別します。これ以上小さくすると本文より小さくなり、見出しに見えなくなります。

章の切れ目の罫線は `article h2` に置きます。記事本文だけが章の切れ目を持つためです。一覧のカードのタイトルも h2 ですが、そちらには上端のアクセント線とタイトル直下の下線があるので、罫線を足すと短い範囲に線が 3 本並びます。

### スペーシング

4px の倍数で、上にいくほど間隔を広げた段を使います。`2xs` が 4px、`xs` が 8px、`sm` が 12px、`md` が 16px、`lg` が 24px、`xl` が 32px、`2xl` が 48px、`3xl` が 64px、`4xl` が 96px です。

本文のブロック間は `blockGap` (32px) を使います。行送りと同じ値にすることで、本文が一定のリズムで流れます。

以前の `verticalRhythmUnit` (1.7rem = 27.2px) をやめたのは、27.2 が 4 の倍数ではないためです。0.125 倍のような小さい刻みを取ると 3.4px が生まれ、アイコンやボーダーと揃わなくなります。

### レイアウト

本文の幅は 760px です。17px で 1 行が全角 44 文字になります。日本語の読みやすさの目安は 35〜45 文字で、その上限側に置きました。800px のときは 16px で 50 文字あり、目安を超えていました。

ブレークポイントは 2 段です。`sm` が 640px、`lg` が 1080px で、`lg` は本文の右に目次を置ける幅にあたります。分岐は `min-width` に統一し、狭いほうを既定として書きます。生の `@media` は書かず、`mediaUp` を通します。

### 角丸・ボーダー・モーション

角丸は 3 段です。`sm` (4px) はインラインコード、タグ、小さいボタンに使います。`md` (8px) はカード、コードブロック、囲みに使います。`full` はアバターとアイコンボタンです。

ボーダーの太さは 1px の 1 段に絞ります。強調する箇所 (引用の左線と一覧カードのアクセント線) だけ 3px を使います。

影は使いません。階層はボーダーと面のカラーで作ります。ダーク背景では影がほとんど見えず、2 テーマ分の値を揃えるのが難しいためです。

モーションは 150ms と 250ms の 2 段、イージングは `ease-out` の 1 種類です。`transition: all` は使わず、対象のプロパティを明示します。動きを減らす設定の読者には `prefers-reduced-motion: reduce` で全停止します。分岐は生の `@media` を書かず、`motion.ts` の `reducedMotion` を通します。

### 状態

フォーカスリングは `:focus-visible` に 1 つだけ、グローバル規則として置きます。accent 色の 2px のリングを 2px のオフセットで描きます。要素ごとに書くと、書き忘れた要素だけキーボードで追えなくなります。`:focus` ではなく `:focus-visible` にするのは、マウスで押した直後にリングが残るのを避けるためです。

リンクの下線は 2 種類です。文章の中に置くリンクは薄い下線を常に引き、hover と focus で accent まで濃くします。前後の記事へのリンクやフッターのように単独で置くリンクは、下線を透明にしておき hover で現れさせます。どちらも `text-decoration-color` を補間します。`text-decoration` の有無は補間できず、hover した瞬間に線が現れて文字が跳ねて見えるためです。

hover では下線を 1px から 2px に太くし、あわせてリンクの背後に `surfaceSubtle` を敷きます。1px の線の色だけを変えても、指しているかどうかが分かりません。

文字の色は hover でも動かしません。accent は白地で 4.91 対 1 しかなく、1 段薄い accent の 400 にすると 3.24 対 1 で本文の基準を割ります。ヘッダーや筆者のリンクが hover で薄くできているのは、text が 15 対 1 近くあって余裕があるためです。面を敷いたときの accent は `surfaceSubtle` の上で 4.67 対 1 で、基準を保ちます。面をこれ以上濃くできないのも同じ理由で、neutral の 100 では 4.08 対 1 になります。

下線の太さと offset は `typography.ts` の `underline` に置きます。ボーダーではなく文字の装飾なので、`shape.ts` の `borderWidth` とは分けます。

文章の中のリンクには、もともとブラウザ既定の下線が引かれていました。これは文字のすぐ下に引かれるため、`g` や `p` の下に伸びる部分と重なります。`text-underline-offset` を 0.2em 取って離しました。

画像は押すと原寸で開きます。それが分かるように、hover で枠を accent にします。

画像の `width` と `height` はビルド時に入れます。寸法が無いと、ブラウザは読み終わるまで高さを 0 として組み、読み終わった時点で下の本文を押し下げます。上限は本文幅の 760px と高さ 500px で、縦に長い画像が画面を占領しないようにします。

面を持つリンクは、面の全体で hover を受けます。一覧のカードはアクセント線が伸びるだけだと動く範囲が狭いので、タイトルの色もあわせて accent にします。リンクカードは以前、本文の領域だけが反応していてサムネイルの上では何も起きなかったので、`a` 側で受けるように直しました。

### アイコン

アイコンは図形をソースに書き、外部から読み込みません。以前は Font Awesome の kit を全ページで読んでいました。実際に使っていたのは GitHub、X、info の 3 つだけです。

ブランドマークの `d` は [Simple Icons](https://simple-icons.org) から取っています。CC0 なので、そのまま持ってきて構いません。info、warning、tip と、テーマの system、light、dark は自前で描いています。円や三角と線だけで済む図形なので、外から持ってくる理由がありません。テーマの system を画面の形にしたのは、太陽と月の中間のような図形にすると、どちらでもない状態が伝わらないためです。

はてなブックマークボタンの `B!` は白地で 2.79 対 1 ですが、ブランドカラーのまま描きます。WCAG 1.4.3 はロゴやブランド名の一部であるテキストをコントラストの対象から外しており、この `B!` ははてなブックマークのロゴそのものだからです。

一度 `text` 色に変えましたが、戻しました。満たす必要のない基準のために、そのボタンが何かを見分けるための手がかりを失っていました。

GitHub と X のマークは、暗い地では白で描きます。どちらも暗い地に置くための白版を配っているので、ブランドの表示としても正しい形です。`theme.ts` に `githubMark` と `xMark` の 2 つの役割を置き、値は `brand.ts` から引いています。役割を 1 つにまとめないのは、ライトでは GitHub が `#211f1f`、X が `#000000` と違う黒を使っているためです。

X のシェアボタンは黒い円のままにします。円そのものがブランドの形なので、色を変えずに `brandSurfaceBorder` で輪郭だけを足しました。円の中の `𝕏` は白で固定します。`textInverted` のままだと、ダークで文字まで暗くなり円に沈みます。

### ダークモード

既定は OS の設定への追従で、読者はヘッダーで明示的に選べます。選択肢は「端末に合わせる」「ライト」「ダーク」の 3 つです。

出ているのは今の選択のアイコンだけで、押すと 3 つの選択肢が開きます。押すたびに巡回する形は避けました。次に何になるかが、押すまで分かりません。「端末に合わせる」を残すのは、一度選んだ後に OS へ戻す道を断たないためです。

`theme.ts` は 3 段構成です。`:root` が既定、`prefers-color-scheme` が OS への追従、`:root[data-theme=...]` が読者の選択で、後ろほど強くなります。選択の側を `:root[data-theme=...]` と書くのは、詳細度で `prefers-color-scheme` の中の `:root` を確実に上回るためです。属性の値は引用符でくくりません。hono/css が補間した文字列の二重引用符をエスケープするためです。

選択は `localStorage` に持ち、head の同期スクリプトが読んで `data-theme` を置きます。同期で置かないと、記憶した色が当たる前に一度描かれ、リロードのたびに色が入れ替わって見えます。`localStorage` は Cookie を全部断る設定のブラウザだと読むだけで例外を投げるので、握りつぶして既定のまま進みます。

部品は `app/islands/ThemePicker.tsx` です。開く一覧はこちらのトークンで組みます。面は `surface`、枠は `border`、角丸は `md` で、影は使いません。項目の角丸だけ `sm` にして、外側の枠と二重の丸みが並ぶのを避けます。今の選択には `surfaceSubtle` を敷きます。色だけで示すと、色の見え方によって選択が読み取れません。

素の `select` はやめました。閉じているうちはこちらで描けますが、開いた一覧はブラウザの見た目のままで、サイトの色や角丸が当たりません。`details` と `summary` も使いません。記事本文の `details` に当てたスタイルがそのまま効いてしまい、打ち消すだけの宣言が並びます。`div` と `button` なら要素の名前でぶつかりません。

そのぶん開閉は自分で持ちます。開いている間だけ、外を押したときと Esc を見ます。閉じるときは引き金のボタンへフォーカスを戻します。戻さないと、キーボードで選んだ後にページの先頭から辿り直すことになります。

出すアイコンは `html` の `data-theme-choice` を見て CSS が選びます。島の状態で選ぶと、水和するまで SSR のときのアイコンが出たままになるためです。一覧の側は開くまで出ないので、そちらの印は島の状態から付けます。選んだときの処理は、同期スクリプトが `window.__applyTheme` として公開しているものを呼びます。適用と保存を 2 箇所に書くと、読み込み直後と選んだ直後で挙動が分かれます。

スクリプトが動かない読者には出しません。`data-theme-choice` が付いたときだけ表示する規則にしてあり、押しても何も起きない部品を見せずに済みます。

置き場所は画面の幅によらずヘッダーの右上です。案内の並びの中に流し込むと、狭い画面でヘッダーがもう 1 行ぶん高くなります。48px の当たり判定はそのまま保ちます。

引き金には枠と地を持たせません。ヘッダーは文字のリンクだけでできていて、箱を持つ要素が 1 つもないので、枠を付けるとここだけ重くなります。hover で `icon` から `text` へ濃くするのは、隣の案内のリンクに合わせたものです。

ヘッダーの `overflow: auto` は `display: flow-root` に替えました。どちらも中の余白がヘッダーの外へ相殺されるのを止めますが、`overflow` は同時にはみ出しも切り落とすため、開いた一覧が見えなくなります。

ビルド時に色が決まるものは、テーマで切り替えません。コードブロックは常にダーク、Mermaid の図は常にライトのままです。図は `rehype-mermaid` がビルド時に線と文字の色まで確定させるので、ダークの地に置くと読めなくなります。`diagramSurface` として図の後ろにだけ白い面を敷き、図だけライトのまま見せます。コードブロックがライトのページで暗いまま置かれているのと同じ扱いです。

インラインコードは地の文に馴染ませる側なので、`surfaceSubtle` と `border` で両テーマとも地に寄せます。

`color-scheme` は `:root` に置きます。スクロールバーやフォーム部品のように、こちらで色を指定していない部分を地に合わせるためです。`theme-color` は `media` 属性で 2 つ書き、値は `theme.ts` の `surface` を書き写します。meta の中では CSS 変数を使えません。読者が明示的に選んだときは、選んだ側の `media` を `all`、もう片方を `not all` に書き換えて、OS ではなく選択のほうを見るようにします。

Twitter の埋め込みは、ウィジェットが `blockquote` の `data-theme` をマウントのときに 1 度だけ読みます。SSG の時点では読者の設定が分からないので、`widgets.js` の読み込みを `DOMContentLoaded` まで遅らせ、属性を付けてから差し込みます。`async` で置いたままだと、属性を付ける前にウィジェットが `blockquote` を拾うことがあります。

## ハーネス

### 見た目の回帰テスト

```shell
pnpm vrt          # 比較する
pnpm vrt:update   # 基準画像を撮り直す
```

ビルドから撮影までを Playwright 公式イメージ (linux/amd64) の中で完結させ、CI も同じイメージの中で回します。9 ページを、デスクトップとモバイル × ライトとダークの 4 組で撮り、36 枚の基準画像を `vrt/__screenshots__/` にコミットします。

Docker が必要です。ホストが macOS だとヒラギノで描かれるため、直接 Playwright を回すと CI と一致しません。

撮る対象はトップ、カテゴリ一覧、タグ一覧、スタイルガイド、記事 5 本です。記事は要素を網羅するように選んであります。`java-catch-up` が表とコードと画像とリンクカード、`isucon11` が 15 列の表、`isucon13` が Mermaid 図、`oauth-2-for-browser-apps` が Note、`enum` が脚注です。

#### 撮影の設計で分かったこと

素の Playwright イメージには和文フォントが 1 つも入っておらず、`sans-serif` が中国語の WenQuanYi Zen Hei に解決されます。Gen Interface JP を 2 ウエイト同梱し、`vrt/fonts/local.conf` で解決先を固定しています。本番のスタイルは触っていないので、読者に見えるフォントは今までどおり OS まかせです。

最初の fullPage 撮影がページ高さを変えます。ビューポートが全高に広がると、それまで可視域の外にあった外部画像がまとめて読み込みに行くためです。捨てる 1 枚を先に撮っています。

外部画像は abort ではなく、決まったプレースホルダを返します。遮断すると、読み込みに失敗した画像の描画が実行ごとに揺れます。

`threshold` の既定値 0.2 では色の変更を検出できません。accent を `#4172b5` から `#4172b8` に変えても 18 ページ中 16 ページが素通りしました。0 に下げてあります。

`maxDiffPixels` と再試行はどちらも 0 です。揺れの原因は 2 つあり、0.5px のサブピクセル境界線をステップ 4 で 1px に揃え、寸法指定のない画像をステップ 7 で解消しました。閾値 0 で 3 回続けて 18 ページとも一致しています。

再試行を残さないのは、撮影の揺れとデザインの変更が同じ「落ちた」で混ざるためです。揺れが無いなら、落ちたことがそのまま変更を意味します。

撮影中にホストで `pnpm build` を回さないでください。コンテナはリポジトリをそのままマウントしていて、`dist/` を共有します。撮影の途中でホストが `dist/` を作り直すと、そのとき出力が揃っていない記事が 404 になり、基準画像の更新がその記事だけ飛びます。

### スタイルガイド

`/styleguide` に、トークンと本文要素とコンポーネントを 1 ページに並べています。トークンの定義をそのまま反復して表にするので、トークンを足せばページにも出ます。一覧の取りこぼしが起きません。

記事ではないので `noindex` を付け、`robots.txt` からも外しています。

見出しは記事本文の中とカードの中の両方の文脈を載せています。一方の文脈だけだと、文脈をまたぐ衝突に気づけません。

フォーカスリングと hover したリンクは、当たった状態を固定で描いた見本を別に置いています。撮影のときカーソルは乗らず、フォーカスも当たりません。そのままだと基準画像に写らないためです。値を二重に書くので、`link.ts` の hover 側を変えたらこの見本も直します。

### ビルド結果の検査

`scripts/check-build-output.mjs` が、ビルドの最後に 2 つを確かめます。

1 つめは全記事に `index.html` があることです。`@hono/vite-ssg` はルートが例外を投げても "Internal Server Error" を本文として書き出し、ビルドを成功させます。Content-Type が `text/plain` になるためファイル名が `index.txt` になり、その記事は本番で 404 になりますが、ログには何も出ません。

2 つめは記事本文に知らない要素が出ていないことです。記事は MDX なので、生の HTML を書けば何でも入ります。スタイルを当てていない要素がブラウザ既定のまま出ると、そこだけ本文のリズムから外れます。一覧は同じファイルの `allowedElements` にあり、要素ごとにスタイルの置き場所を書いてあります。要素を足すときは、先にスタイルを当ててから一覧に足してください。

`svg` の中は数えません。Mermaid と埋め込みが持つ領域で、こちらでスタイルを当てないためです。`foreignObject` の中には `div` や `span` が入るので、要素名だけで外すと本文のものと見分けが付きません。部分木ごと飛ばしています。

### コントラストの検証

`app/styles/theme.test.ts` が役割の組み合わせ 15 通りについて WCAG 2.2 の比を計算します。本文 4.5 対 1、大きい文字と UI 部品 3 対 1 を下回ったら落とします。ライトとダークの両方で回すので 30 件になります。テーマを足すときは `themes` に 1 行足すだけで、同じ 15 通りがそのテーマでも検証されます。

片方のテーマでしか比を持たない役割は、この表から外して個別のテストへ書きます。`brandSurfaceBorder` はライトでは透明で、比較する相手がありません。16 進数でない値を渡すと相対輝度が NaN になり、比較が静かに通ってしまうので、`relativeLuminance` は形式を確かめて落とします。

`app/styles/brand.ts` は対象外です。他社のブランドカラーは動かせないので、比を満たすかどうかはこちらで決められません。WCAG 1.4.3 も、ロゴやブランド名の一部であるテキストをコントラストの対象から外しています。

### まだ入れていないハーネス

生の値 (hex、px、`@media`、`box-shadow`) を検出する lint です。最終的に error にして CI で落とします。既存の違反を許可リストに載せ、PR ごとに減らす形を想定しています。

## 落とし穴

作業中に踏んだもので、次に同じ場所を触る人が踏みそうなものを残します。

### hono/css の `:-hono-global` は 1 行に収まらないと展開されない

判定が `/^:-hono-global{(.*)}$/` で、`.` は改行に一致しません。テンプレートの中に複数行のコメントを入れると最小化後も改行が残り、クラスの中に入れ子のまま出力されます。

この状態では CSS 全体が無効になります。`body` の指定と `code.hljs` の `overflow-x` が適用されず、コードブロックが横に広がってページ全体がスクロールしました。

グローバルブロックの説明は、テンプレートの外に書いてください。

### hono/css は補間した値の二重引用符をエスケープする

`font-family` をトークンから差し込むと、その宣言が無効になります。CSS のフォント名は識別子の並びとして書けるので、引用符は付けません。

テンプレートに直接書いた文字列は素通しです。値を定数へ切り出したときに初めて表面化します。

### ショートハンドは、先に書いた指定を初期値に戻す

`text-decoration: underline` は `text-decoration-color` を currentColor に戻します。`${...}` で取り込んだスタイルの中にこのショートハンドがあると、取り込む側が先に書いた色が消えます。

ステップ 5 でこれを踏みました。「入れ子の規則の後ろに宣言を書かない」に合わせて `${...}` を末尾へ動かした結果、色の指定がショートハンドより前に来ました。前後の記事リンクとフッターは常時下線が出たままになり、本文のリンクの下線は `accentMuted` ではなく accent で描かれていました。ショートハンドではなく `text-decoration-line` を書けば、順序に関わらず残ります。

見た目の回帰テストは 18 ページすべての差分を出していましたが、想定どおりの変更に紛れていました。基準画像を受け入れる前に実物を開いて気づいたものです。

### 定義していないクラスは、無いことに気づけない

脚注の見出しは remark が `<h2 class="sr-only">Footnotes</h2>` として出力します。その `sr-only` はどこにも定義がなく、英語の「Footnotes」が章の罫線つきで 6 記事に出ていました。

クラス名が付いていると、見た目が整っているように見えます。CSS 側に定義が無いことは、出力を読むまで分かりません。プラグインが吐くクラス名は、頼る前に生成物を検索してください。

### hono/css のクラスをセレクタに差し込まない

`&:hover ${entryBodyCss} { ... }` のように、クラスを `${...}` でセレクタの位置に書くと、クラス名ではなく中身の宣言がそのまま展開されることもあります。展開された規則は、全体が読めなくなります。

リンクカードでこれを踏みました。`&:hover ` の後ろにカード本文の宣言が並び、`flex-direction: column` と `padding` がカードのリンクそのものに当たって、サムネイルと本文が縦に積まれました。

同じ書き方でも、クラス名として出る場合があります。単独のセレクタでは出て、カンマで 2 つ並べた側では展開されました。どちらになるか読めません。中の要素は `Note` と同じように素のクラス名で指してください。クラスは `cx()` で足します。テンプレートリテラルで文字列としてつなぐと、SSR の最中に `document is not defined` で落ちます。

### 入れ子の規則の後ろに宣言を書かない

hono/css は `&:hover` をそのまま出力し、入れ子の解決はブラウザに任せます。CSS Nesting では、入れ子の規則より後ろに書いた宣言を拾えるようになったのが 2024 年のブラウザからで、それより前は捨てられます。

`${...}` で他のスタイルを取り込むと、この形が意図せず生まれます。取り込んだ側が `&:hover` を持っていると、その後ろに書いた `text-align` や `background-color` が入れ子のブロックの外に出ます。シェアボタンの黒地と、ページ送りの矢印の寄せがこの形でした。

`${...}` は最後に置いてください。

### CSS のコメントに波括弧を書かない

hono/css の最小化はコメントを読み飛ばしません。コメントの中の `{` や `}` が波括弧の対応付けを狂わせます。

### 長い URL は折り返せない

リンクのテキストが URL そのものになっている箇所があります。区切りがないためどこでも折り返せず、本文幅を狭めると画面からはみ出します。`overflow-wrap: break-word` を `body` に置いてあります。

### Mermaid の図はビルド環境によって寸法が変わる

`rehype-mermaid` はビルド時に Playwright で文字幅を実測して座標を決めます。ホストでビルドすると図の座標がずれるため、VRT はビルドもコンテナの中で行います。

同じコンテナの中でも、ビルドのたびに図がわずかに動くことがあります。ステップ 8 で基準画像を撮り直したとき、図に触れていないのに `isucon13` だけ 34 ピクセル分の差が出ました。差は 450x89 の範囲に収まり、明るさの差は最大で 10 でした。撮り直した後に 2 度目を回すと 36 枚とも一致したので、揺れるのは撮影ではなくビルドの側です。`maxDiffPixels` が 0 なので、この記事だけ CI がまれに落ちる可能性があります。落ちたときは差分の位置を見て、図の中だけなら撮り直してください。

### VRT は変化を検出するが、良し悪しは判断しない

タイポグラフィを当てたとき 18 ページすべてが同時に落ちました。まとめて想定どおりとして受け入れた結果、一覧のタイトルに罫線が出ていたことを見落としました。基準画像には写っていました。

全ページが一斉に変わる変更では、少なくともスタイルガイドとトップと記事の 3 枚は開いてください。
