# デザインシステム

## このドキュメントについて

このブログのデザインシステムの仕様と、その構築作業の進捗をまとめています。

新しいセッションを始めるときは、このドキュメントと [CONTEXT.md](../CONTEXT.md) と [CLAUDE.md](../CLAUDE.md) を読んでください。用語の定義は CONTEXT.md、コードの書き方は CLAUDE.md にあります。基盤の改善計画は [refactoring-plan.md](refactoring-plan.md) にあり、そちらのステップ 6 (OGP の内製化) と 7 (ダークモードと TOC) はまだ残っています。

進捗は「作業ステップ」の各見出しにある状態欄で管理します。ステップを終えたら状態を更新してください。

## なぜこの作業をするのか

このブログの見た目は、必要になるたび値を足す形で作られてきました。その結果、同じ役割でも場所ごとに違う値が使われています。

調査した時点で、font-size は 17 種類ありました。`12px` `13px` `14px` `17px` `22px` `0.8rem` `0.85rem` `0.9rem` `1.1rem` `1.2rem` `1.3rem` `1.5rem` `1.5em` `1.75rem` `2rem` `2.5rem` `85%` です。余白は `1.7rem` の倍数と生の値が混ざり、境界線は `0.5px` `1px` `0.2rem` `0.25rem` が並立していました。

この状態では、AI が新しいコンポーネントを書くときに参照する基準がありません。既存のコードを真似ても、真似た先の値が正しいとは限らないためです。

そこで値を役割ごとのトークンに寄せ、そこから外れた変更を機械的に検出できるようにします。

## 決定事項

ここに書いた内容は合意済みです。実装中に前提が崩れた場合は、このドキュメントを更新してから進めてください。

### 前提

| 項目 | 決定 |
| --- | --- |
| 見た目の変更 | 骨格は保ち、不揃いと破綻だけ直す |
| ハーネスの対象 | 記事の MDX、既存コンポーネントの改修、新規コンポーネントの追加 |
| ダークモード | 最初から 2 テーマ分の値を持つ前提で設計し、OS 設定への追従は今回のリリースで有効にする |
| アクセシビリティ | WCAG 2.2 AA。両テーマで自動検証し、下回ったら CI で落とす |
| ドキュメント | このファイルに集約する。ADR は書かない |

### トークン

色は値そのものと役割の 2 層に分けます。`app/styles/palette.ts` が色そのものの名前を持ち、`app/styles/theme.ts` が役割への割り当てを持ちます。コンポーネントから見えるのは `app/styles/color.ts` の役割名だけです。

役割名だけだと、テーマを 2 つ持ったときにダーク側の値を決める基準がなくなります。

色以外はテーマで変わらないので、型付きの TypeScript の定数として持ちます。

| ファイル | 内容 |
| --- | --- |
| `palette.ts` | 色の値そのもの。色相 215〜216 度の 1 系統で、neutral が 12 段、accent が 9 段 |
| `theme.ts` | 役割への割り当て。テーマを足すときは同じ形の表をもう 1 つ書く |
| `color.ts` | 役割名。`var(--color-*)` を返す |
| `typography.ts` | 文字の大きさ、行間、太さ、書体 |
| `spacing.ts` | 余白。4px の倍数 |
| `shape.ts` | 角丸と境界線の太さ |
| `motion.ts` | 動きの長さと曲線 |
| `breakpoint.ts` | 画面幅の分岐点と本文幅 |

### 色

既存の 11 色を測りました。text が 218 度、textMuted が 215 度、border が 214 度、icon が 216 度、accent が 215 度で、すべて 214〜218 度に収まっています。もともと 1 色相の濃淡でできていたので、それを明示して隙間を埋めただけになっています。既存の値はすべて段のどれかとして残してあります。

accent の 500 は OG 画像の下辺のボーダーにも使っている事実上のブランド色なので動かしません。

ダーク側のコントラストは、地を neutral の 950 相当としたときに次の値になります。本文は neutral の 200 で 13.42 対 1、textMuted は neutral の 400 で 6.01 対 1、accent は accent の 300 で 7.63 対 1 です。3 つとも AA を超えます。

### タイポグラフィ

本文 17px を基準に、比 1.2 の等比で組みます。名前は用途で付けます。段の番号にすると「見出しにはどれか」を毎回決め直すことになりますが、用途名なら書くものから引けます。

| 名前 | 値 | 用途 |
| --- | --- | --- |
| `caption` | 13px | 日付やキャプション |
| `bodySmall` | 15px | リンクカードの説明などの補助的な本文 |
| `body` | 17px | 記事の地の文 |
| `h4` | 20px | |
| `h3` | 24px | |
| `h2` | 28px | |
| `h1` | 34px | 記事タイトルとサイト名 |
| `code` | 14px | コードブロック |

行間は本文 1.9、見出し 1.4、1 行で収まるもの 1.25 です。倍率で持ち、px では持ちません。px にすると文字サイズを変えたときに追従しません。

書体は読者の OS のものを使います。Web フォントを入れないのは表示速度を保つためで、見た目の伸びしろは書体そのものより行長と行間と大きさの整理のほうが大きいと判断しました。

h5 と h6 は本文と同じ大きさにして太さだけで区別します。これ以上小さくすると本文より小さくなり、見出しに見えなくなります。

章の切れ目の罫線は `article h2` に置きます。記事本文だけが章の切れ目を持つためです。一覧のカードのタイトルも h2 ですが、そちらには上端のアクセント線とタイトル直下の下線があるので、罫線を足すと短い範囲に線が 3 本並びます。

### 余白

4px の倍数で、上にいくほど間隔を広げた段を使います。`2xs` が 4px、`xs` が 8px、`sm` が 12px、`md` が 16px、`lg` が 24px、`xl` が 32px、`2xl` が 48px、`3xl` が 64px、`4xl` が 96px です。

本文のブロック間は `blockGap` (32px) を使います。行送りと同じ値にすることで、本文が一定のリズムで流れます。

以前の `verticalRhythmUnit` (1.7rem = 27.2px) をやめたのは、27.2 が 4 の倍数ではないためです。0.125 倍のような小さい刻みを取ると 3.4px が生まれ、アイコンや境界線と揃わなくなります。

### レイアウト

本文の幅は 760px です。17px で 1 行が全角 44 文字になります。日本語の読みやすさの目安は 35〜45 文字で、その上限側に置きました。800px のときは 16px で 50 文字あり、目安を超えていました。

画面幅の分岐は 2 段です。`sm` が 640px、`lg` が 1080px で、`lg` は本文の右に目次を置ける幅にあたります。分岐は `min-width` に統一し、狭いほうを既定として書きます。生の `@media` は書かず、`mediaUp` を通します。

### 形と動き

角丸は 3 段です。`sm` (4px) はインラインコード、タグ、小さいボタンに使います。`md` (8px) はカード、コードブロック、囲みに使います。`full` はアバターとアイコンボタンです。

境界線の太さは 1px の 1 段に絞ります。強調する箇所 (引用の左線と一覧カードのアクセント線) だけ 3px を使います。

影は使いません。階層は境界線と面色で作ります。ダーク背景では影がほとんど見えず、2 テーマ分の値を揃えるのが難しいためです。

動きは 150ms と 250ms の 2 段、曲線は `ease-out` の 1 種類です。`transition: all` は使わず、対象のプロパティを明示します。

### まだ決めてあるが未実装のもの

- 本文中のリンクは薄い下線を引き、hover で濃くする
- `:focus-visible` に accent 色の 2px のリングと 2px のオフセットを当てるグローバル規則を 1 つ置く
- `prefers-reduced-motion: reduce` で動きを全停止する
- コードブロックは常時ダークのまま維持する。インラインコードは地の文に馴染ませ、別の役割として扱う
- 記事で使う HTML 要素を全部列挙して全部にスタイルを当て、一覧にない要素が現れたら CI で落とす
- `Note` に 3 種別 (info / warning / tip) を足す。既定値は info

## ハーネス

### 見た目の回帰テスト

```shell
pnpm vrt          # 比較する
pnpm vrt:update   # 基準画像を撮り直す
```

ビルドから撮影までを Playwright 公式イメージ (linux/amd64) の中で完結させ、CI も同じイメージの中で回します。9 ページをデスクトップとモバイルで撮り、基準画像は `vrt/__screenshots__/` にコミットします。

Docker が必要です。ホストが macOS だとヒラギノで描かれるため、直接 Playwright を回すと CI と一致しません。

撮る対象はトップ、カテゴリ一覧、タグ一覧、スタイルガイド、記事 5 本です。記事は要素を網羅するように選んであります。`java-catch-up` が表とコードと画像とリンクカード、`isucon11` が 15 列の表、`isucon13` が Mermaid 図、`oauth-2-for-browser-apps` が Note、`enum` が脚注です。

#### 撮影の設計で分かったこと

素の Playwright イメージには和文フォントが 1 つも入っておらず、`sans-serif` が中国語の WenQuanYi Zen Hei に解決されます。Gen Interface JP を 2 ウエイト同梱し、`vrt/fonts/local.conf` で解決先を固定しています。本番のスタイルは触っていないので、読者に見える書体は今までどおり OS まかせです。

最初の fullPage 撮影がページ高さを変えます。ビューポートが全高に広がると、それまで可視域の外にあった外部画像がまとめて読み込みに行くためです。捨てる 1 枚を先に撮っています。

外部画像は abort ではなく、決まったプレースホルダを返します。遮断すると、読み込みに失敗した画像の描画が実行ごとに揺れます。

`threshold` の既定値 0.2 では色の変更を検出できません。accent を `#4172b5` から `#4172b8` に変えても 18 ページ中 16 ページが素通りしました。0 に下げてあります。

`maxDiffPixels` は 800、再試行は 2 回です。境界線の太さを 1px に揃えたので、この 2 つは締められる見込みです。

### スタイルガイド

`/styleguide` に、トークンと本文要素とコンポーネントを 1 ページに並べています。トークンの定義をそのまま反復して表にするので、トークンを足せばページにも出ます。一覧の取りこぼしが起きません。

記事ではないので `noindex` を付け、`robots.txt` からも外しています。

見出しは記事本文の中とカードの中の両方の文脈を載せています。一方の文脈だけだと、文脈をまたぐ衝突に気づけません。

### ビルド結果の検査

`scripts/check-build-output.mjs` が、全記事に `index.html` があることをビルドの最後に確かめます。

`@hono/vite-ssg` はルートが例外を投げても "Internal Server Error" を本文として書き出し、ビルドを成功させます。Content-Type が `text/plain` になるためファイル名が `index.txt` になり、その記事は本番で 404 になりますが、ログには何も出ません。

### コントラストの検証

`app/styles/theme.test.ts` が役割の組み合わせ 9 通りについて WCAG 2.2 の比を計算します。本文 4.5 対 1、大きい文字と UI 部品 3 対 1 を下回ったら落とします。テーマを足すときは `themes` に 1 行足せば、同じ 9 通りが両テーマで検証されます。

### まだ入れていないハーネス

生の値 (hex、px、`@media`、`box-shadow`) を検出する lint です。最終的に error にして CI で落とします。既存の違反を許可リストに載せ、PR ごとに減らす形を想定しています。

## 落とし穴

作業中に踏んだもので、次に同じ場所を触る人が踏みそうなものを残します。

### hono/css の `:-hono-global` は 1 行に収まらないと展開されない

判定が `/^:-hono-global{(.*)}$/` で、`.` は改行に一致しません。テンプレートの中に複数行のコメントを入れると最小化後も改行が残り、クラスの中に入れ子のまま出力されます。

この状態では CSS 全体が無効になります。`body` の指定と `code.hljs` の `overflow-x` が適用されず、コードブロックが横に広がってページ全体がスクロールしました。

グローバルブロックの説明は、テンプレートの外に書いてください。

### hono/css は補間した値の二重引用符をエスケープする

`font-family` をトークンから差し込むと、その宣言が無効になります。CSS のフォント名は識別子の並びとして書けるので、引用符は付けません。

テンプレートに直接書いた文字列は素通しです。値を定数へ切り出したときに初めて表面化します。

### CSS のコメントに波括弧を書かない

hono/css の最小化はコメントを読み飛ばしません。コメントの中の `{` や `}` が波括弧の対応付けを狂わせます。

### 長い URL は折り返せない

リンクのテキストが URL そのものになっている箇所があります。区切りがないためどこでも折り返せず、本文幅を狭めると画面からはみ出します。`overflow-wrap: break-word` を `body` に置いてあります。

### Mermaid の図はビルド環境によって寸法が変わる

`rehype-mermaid` はビルド時に Playwright で文字幅を実測して座標を決めます。ホストでビルドすると図の座標がずれるため、VRT はビルドもコンテナの中で行います。

### VRT は変化を検出するが、良し悪しは判断しない

タイポグラフィを当てたとき 18 ページすべてが同時に落ちました。まとめて想定どおりとして受け入れた結果、一覧のタイトルに罫線が出ていたことを見落としました。基準画像には写っていました。

全ページが一斉に変わる変更では、少なくともスタイルガイドとトップと記事の 3 枚は開いてください。
