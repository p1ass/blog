# 誤字脱字・表記のレビュー

記事を 1 文ずつ読み、明確な誤りを検出する。**指摘の対象は客観的な誤りに限る。**

## 見るもの

### 誤字脱字

- 変換ミス、タイプミス、脱字、衍字
- 助詞の誤り (「を」と「が」、「に」と「へ」)
- 送り仮名の誤り (「行なう」→「行う」、「表わす」→「表す」)
- 呼応の誤り (「決して〜する」→「決して〜しない」)

### 表記ゆれ

同じ記事の中で表記が揺れている箇所を検出する。

- 固有名詞 (`GitHub` / `Github`、`Next.js` / `NextJS`、`Cloudflare` / `CloudFlare`)
- カタカナ語の長音 (`サーバー` / `サーバ`、`ユーザー` / `ユーザ`)
- 漢字とひらがな (`事` / `こと`、`出来る` / `できる`、`為` / `ため`)
- 数字の全角と半角

揺れの判定は記事内で完結させる。過去記事全体との照合は対象外とする。

### 半角と全角の間のスペース

このブログは**半角英数と日本語の間に半角スペースを入れる**規約とする。

- 良い: `Claude Code Action を使って PR をレビューする`
- 悪い: `Claude Code Actionを使ってPRをレビューする`

句読点の前後は詰める。インラインコードの前後にはスペースを入れる。

抜けている箇所を指摘する。**1 記事で 10 箇所を超える場合はまとめて 1 件の指摘にする。**

### 文法的な誤り

- 主語と述語の不一致
- 修飾関係が曖昧な箇所 (どこにかかるか 2 通りに読める)
- 一文に主語が複数あって係り受けが崩れている箇所
- 二重否定、二重敬語

### 数字と単位

- 数字の桁区切りの有無が揃っているか
- 単位の表記が揃っているか (`ms` / `ミリ秒`)
- 本文中の数字と、図表やコードブロック内の数字が矛盾していないか

## 出力

各指摘を次の形式で書く。

```
#### [ラベル] 短い指摘タイトル
- 観点: 誤字脱字・表記
- 箇所: <ファイルパス>:<行番号>
- 影響: <読者にどう影響するか>
- 根拠: <なぜ誤りと言えるか。該当箇所の引用を含める>
- 改善案: <具体的な修正文>
```

ラベルは `must` (意味が変わる誤り) / `should` (読みにくさ・表記ゆれ) / `nits` (些末) / `question` (判断できない) から選ぶ。

## 指摘の対象外

- 文体や表現の好み
- `.claude/skills/blog-writing/references/style.md` に定義された筆者固有のスタイル
- MDX コンポーネント (`<ExLinkCard>` `<Twitter>` `<BlockLink>` `<Note>`)
- `{/* <!--more--> */}` マーカー
- 画像直下の `_キャプション_`
- `<!-- TODO: ... -->` コメント
- コードブロックの中身: 技術的な誤りは tech-review の担当
