# 誤字脱字・表記のレビュー

記事を 1 文ずつ精読し、客観的・明確な誤りを検出する。**指摘の対象は主観的な好みではなく、客観的な誤りに限定する。**

## レビュー観点

### 誤字脱字

- 変換ミス、タイプミス、脱字、衍字
- 助詞の誤用（例:「を」と「が」、「に」と「へ」の取り違え）
- 送り仮名の誤り（例:「行なう」→「行う」、「表わす」→「表す」）
- 呼応の誤り（例:「決して〜する」→「決して〜しない」）

### 表記ゆれ

同一記事内で表記が不揃いになっている箇所を検出する。

- 固有名詞（例: `GitHub` / `Github`、`Next.js` / `NextJS`、`Cloudflare` / `CloudFlare`）
- カタカナ語の長音（例: `サーバー` / `サーバ`、`ユーザー` / `ユーザ`）
- 漢字とひらがなの使い分け（例: `事` / `こと`、`出来る` / `できる`、`為` / `ため`）
- 数字の全角と半角

表記ゆれの判定は当該記事内だけで完結させるものとし、過去記事全体との比較は対象外とする。

### 半角英数と日本語の間のスペース

当ブログでは、**半角英数と日本語の間に半角スペースを挿入する**規約としている。

- 良い例: `Claude Code Action を使って PR をレビューする`
- 悪い例: `Claude Code Actionを使ってPRをレビューする`

句読点の前後はスペースを空けずに詰める。インラインコード記法（``）の前後には半角スペースを入れる。

スペースが抜けている箇所を指摘する。**1 記事内に 10 箇所以上ある場合は、個別に羅列せず 1 件の指摘にまとめる。**

### 文法的な誤り

- 主語と述語の不一致
- 修飾関係が曖昧な文（複数の解釈が生じる修飾のねじれ）
- 1 文の中に主語や述語が混在し、係り受けが崩れている文
- 二重否定、二重敬語などの不自然な表現

### 数字と単位

- 数字の桁区切り（カンマ）の有無が統一されているか
- 単位の表記が統一されているか（例: `ms` と `ミリ秒` など）
- 本文中の数値と、図表やコードブロック内の数値に矛盾がないか

## 出力

各指摘を次の形式で記述する。

```
#### [ラベル] 短い指摘タイトル
- 観点: 誤字脱字・表記
- 箇所: <ファイルパス>:<行番号>
- 影響: <読者にどう影響するか>
- 根拠: <なぜ誤りと言えるか。該当箇所の引用を含める>
- 改善案: <具体的な修正文>
```

ラベルは `must`（意味や事実が変わってしまう誤り）/ `should`（読みにくさや表記ゆれ）/ `nits`（軽微な指摘）/ `question`（誤りかどうか判断がつかない箇所）から選択する。

## 指摘の対象外

- 文体や表現の好み
- `.claude/skills/blog-writing/references/style.md` に定義された筆者固有のスタイル
- MDX コンポーネント（`<ExLinkCard>`、`<Twitter>`、`<BlockLink>`、`<Note>`）
- `{/* <!--more--> */}` マーカー
- 画像直下の `_キャプション_`
- `<!-- TODO: ... -->` コメント
- コードブロックの中身（技術的な正確性の検証は `tech-review` の担当とする）
