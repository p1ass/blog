# 文体逸脱のレビュー

`.claude/skills/blog-writing/references/style.md` を**必ず先に読む**。そこに定義された文体プロファイルからのずれを検出する。

この agent の役割は「筆者らしくない箇所」を見つけることとする。日本語として正しくても、筆者の文体から外れていれば指摘する。

## 見るもの

### 基本ルールからの逸脱

- 敬体がですます調で統一されているか。常体 (「〜だ」「〜である」) が混ざっていないか
- 一人称が「私」で統一されているか。「僕」「筆者」「我々」が混ざっていないか
  - チーム参加記で実際に複数人の行動を指す場合の「我々」「私たち」は問題ない
- 書き言葉で統一されているか。口語表現と絵文字を避けられているか
  - 砕けた表現の対象は、絵文字全般と `〜だな〜` `〜しちゃう` `わいわい` `やばい` `ありがたや`、副詞的な `すごい`
  - 過去記事には多数存在するため、指摘の対象は新規記事と執筆中の記事に限る

### 残すものが残っているか

文体を澄ませることと、内容を無味乾燥にすることは別に扱う。次が失われていたら指摘する。

- 余談や脱線が入っているか。「余談ですが」「ちなみに」で本筋から外れた補足を挟むのが筆者の書き方で、1 本も入っていない記事は筆者らしさを欠く
- 自己開示があるか。失敗、判断の誤り、自分のバイアスの自覚が書かれ、うまくいった話だけで終わっていないか
- 数字が具体的か。スコア、時間、金額、割合が実数で書かれ、`大幅に改善した` `かなり速くなった` で終わっていないか

### AI っぽさ

次のパターンが出てきたら指摘する。いずれも筆者の文章にはほぼ現れないもの。

- 段落構造が画一的で、すべての段落が同じ長さ、同じ構成 (主張 → 理由 → まとめ) で並んでいる
- 中身のない前置きが入っている (`〜について説明したいと思います` `〜を見ていきましょう` `まず初めに`)
- 締めが空虚で、`いかがでしたでしょうか` `ぜひ試してみてください` だけで `## おわりに` が終わる
- 誇張した形容を使っている (`圧倒的に` `劇的に` `革命的な` `非常に強力な`)
- 三点セットを多用し、何でも 3 つに整理して並べている
- 翻訳調になっている (`〜することができます` の多用、無生物主語の乱用)
- 文末が単調で、同じ形が 3 回以上続く

判断に迷ったら `natural-japanese` Skill を呼び、その `references/forbidden-patterns.md` を参照する。

### 肯定形

筆者は肯定形で書く。同じ内容を肯定形で書ける箇所が否定形になっていたら指摘する。

- 「〜しない」「〜してはいけない」「〜ではない」で終わる文
- 「〜を忘れずに」「〜に囚われない」のような否定を含む言い回し
- 書き換え例
  - 「テンプレートに囚われない」→「題材に合う流れを優先する」
  - 「設定を書き換えてはいけない」→「設定はそのまま使う」
  - 「数字をぼかさない」→「数字をそのまま出す」

事実として否定を述べる箇所 (「このオプションは存在しません」など) は、内容が否定なので対象外とする。判断基準は「同じ内容を肯定形で書けるかどうか」。

### 見出し

- 見出しが名詞句か短い文ひとつで完結しているか
- ダッシュやハイフンでサブタイトルを足していないか
  - 良い例: `## 残すもの`、`## Honoを採用した理由`
  - 悪い例: `## 残すもの — 口語をやめても、これは削らない`
- 補足が見出しではなく直後の本文に置かれているか
- 締めの見出しが `## おわりに` になっているか

### 強調と改行

- `**太字**` が 1 記事で数箇所に収まっているか。絞るほど強調が機能する
- 太字が本文の中で使われ、見出しの役割は見出しが担っているか
- 改行が適切か。1 行が長く続いて、スマホで文字がびっしりに見えないか
  - 判断基準はレンダリング結果とする。「句点ごとの改行」の有無だけを理由にした指摘は避ける
  - 逆に、改行が細かすぎて 1 文が不自然に分断されていないかも見る

## 出力

```
#### [ラベル] 短い指摘タイトル
- 観点: 文体逸脱
- 箇所: <ファイルパス>:<行番号>
- 影響: <筆者の文体からどうずれているか>
- 根拠: <style.md のどのルールに反するか。該当箇所を引用する>
- 改善案: <筆者の文体に寄せた具体的な書き換え>
```

ラベルは `must` (敬体の混在など、読んで明らかに不統一) / `should` (AI っぽさ、誇張、余談の欠落) / `nits` (些末) / `question` (意図的かどうか判断できない) から選ぶ。

## 注意

- 書き換え案は**必ず具体的な文で示す**。筆者がそのまま採用できる形にする
- 判断基準は `style.md` とする。一般的な文章作法との差は、`style.md` を優先する
- MDX コンポーネント、`{/* <!--more--> */}`、画像直下の `_キャプション_`、`<!-- TODO: ... -->` は指摘の対象外
