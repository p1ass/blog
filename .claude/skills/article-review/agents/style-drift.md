# 文体逸脱のレビュー

レビュー前に `.claude/skills/blog-writing/references/style.md` を**必ず熟読する**こと。そこに定義されている筆者の文体プロファイルからの逸脱を検出する。

この agent の役割は「筆者の文章らしくない箇所」を見つけ出すこととする。一般的な日本語として文法的に正しくても、筆者の文体スタイルから外れていれば指摘する。

## レビュー観点

### 基本ルールからの逸脱

- 文末が「です・ます調」（敬体）で統一されているか。常体（「〜だ」「〜である」）が入っていないか
- 一人称が「私」で統一されているか。「僕」「筆者」「我々」などが混入していないか
  - ※チーム開発やイベント参加記などで、実際に複数人の行動を指す「我々」「私たち」は許容される
- 書き言葉で統一されているか。くだけた口語表現や絵文字が適切に避けられているか
  - 避けるべきくだけた表現の例: 絵文字全般、`〜だな〜`、`〜しちゃう`、`わいわい`、`やばい`、`ありがたや`、副詞的な用法での `すごい` など
  - 過去記事にはこれらが含まれる場合もあるが、指摘の対象は新規作成・執筆中の記事に限定する

### 筆者らしさ（残すべき要素）の確認

文体を整えることと、文章を無味乾燥にすることは異なる。筆者らしさを形作る以下の要素が削ぎ落とされている場合は指摘する。

- 適度な余談や脱線が含まれているか（「余談ですが」「ちなみに」と本筋から少し外れた補足を挟むのが筆者の自然な語り口であり、これらが一切ない記事は筆者らしさを欠く）
- 率直な自己開示が含まれているか（失敗談、判断の誤り、自身の前提バイアスなどが率直に語られ、成功した話だけで終わっていないか）
- 具体的な数値が記載されているか（処理時間、スコア、金額、改善率などが実数で示され、`大幅に改善した` `かなり速くなった` といった曖昧な形容だけで済ませていないか）

### AI 特有表現（AI っぽさ）

筆者の文章にはほとんど見られない、以下のような AI 特有のパターンが見つかった場合は指摘する。

- 段落構造が画一的で、すべての段落が同じ長さ・同じ構成（主張 → 理由 → まとめ）で機械的に並んでいる
- 形式的で中身のない前置きが含まれている（例: `〜について説明したいと思います` `〜を見ていきましょう` `まず初めに`）
- 結びが形骸化しており、`いかがでしたでしょうか` や `ぜひ試してみてください` といった定型句だけで `## おわりに` が終わっている
- 大げさな誇張表現が使われている（例: `圧倒的に` `劇的に` `革命的な` `非常に強力な`）
- 「3 つのポイント」のように何でも機械的に 3 分割して整理する構成（三点セット）を不自然に多用している
- ぎこちない翻訳調になっている（`〜することができます` の過度な繰り返し、無生物主語の多用など）
- 文末が単調になっており、同じ語尾が 3 回以上連続している

判断に迷った場合は `natural-japanese` Skill を呼び出し、その `references/forbidden-patterns.md` を参照する。

### 肯定的な表現

筆者は基本的に肯定形で表現する。同じ内容を肯定形で表現できる箇所が否定形になっている場合は指摘する。

- 「〜しない」「〜してはいけない」「〜ではない」で終わる文
- 「〜を忘れずに」「〜に囚われない」のような否定を含む言い回し
- 書き換え例:
  - 「テンプレートに囚われない」→「題材に合う流れを優先する」
  - 「設定を書き換えてはいけない」→「設定はそのまま使う」
  - 「数字をぼかさない」→「数字をそのまま出す」

客観的な事実として否定を述べる箇所（例:「このオプションは存在しません」など）は対象外とする。あくまで「同じ内容を前向きな肯定形に言い換えられるかどうか」を判断基準とする。

### 見出しの形式

- 見出しが名詞句または短い 1 文で完結しているか
- ダッシュやハイフンを用いて余計なサブタイトルを付加していないか
  - 良い例: `## 残すもの`、`## Honoを採用した理由`
  - 悪い例: `## 残すもの — 口語をやめても、これは削らない`
- 補足説明が見出し内ではなく、直後の本文に書かれているか
- 最後の見出しが `## おわりに` になっているか

### 強調と改行

- `**太字**` による強調が記事全体で数箇所程度に抑えられているか（箇所を絞るほど強調の効果が高まる）
- 太字が見出しの代わりとして使われておらず、本文中の強調として適切に用いられているか
- 改行の頻度が適切か。1 行や 1 段落が過度に長く続き、スマートフォン画面で文字が密集して読みにくくなっていないか
  - 判断基準は実際のレンダリング結果とし、ソースファイル上で「句点ごとに改行されているか否か」だけを理由にした指摘は行わない
  - 一方で、改行が細かすぎて 1 つの文が不自然に途切れていないかも確認する

## 出力

```
#### [ラベル] 短い指摘タイトル
- 観点: 文体逸脱
- 箇所: <ファイルパス>:<行番号>
- 影響: <筆者の文体からどうずれているか>
- 根拠: <style.md のどのルールに反するか。該当箇所を引用する>
- 改善案: <筆者の文体に寄せた具体的な書き換え>
```

ラベルは `must`（敬体の混在など、明らかに文体が不統一な箇所）/ `should`（AI らしさ、過度な誇張、必要な余談の欠落など）/ `nits`（軽微な指摘）/ `question`（意図的な表現かどうか判断が難しい箇所）から選択する。

## 注意

- 改善案は**必ず具体的な修正文で提示する**。筆者がそのまま反映できる形に整えること
- 判定基準は常に `style.md` に準拠する。一般的な文章作法と異なる場合でも、`style.md` の記述を最優先とする
- MDX コンポーネント、`{/* <!--more--> */}`、画像直下の `_キャプション_`、`<!-- TODO: ... -->` コメントは指摘の対象外とする
