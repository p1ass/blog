# 技術記事の技術レビューチェックリスト

記事の性質に応じて該当する項目を適用し、影響度の大きい問題を優先して検証する。網羅性よりも読者への影響の大きさを重視する。

## 主張と根拠

- 中心となる事実関係が、一次情報または記録された観測結果によって裏付けられているか
- バージョンに依存する記述について、最新の公式ドキュメント等で現在の状況を確認しているか
- 仕様書や公式文書の記述を、前後の文脈や本来の意図に沿って正確に説明しているか
- 「〜できない」「〜は存在しない」といった主張を、一次情報で実際に確認しているか
- 記事中に貼られたリンクが、該当箇所の主張を実際に裏付けているか
- 引用文が原典と正確に一致しており、文脈を損なわずに提示されているか
- アーキテクチャや設計理由の記述が、公式資料等で確認できる客観的事実の範囲に収まっているか
- 事実、観測結果、推論、筆者の個人的意見が明確に区別されているか
- 個人ブログや Q&A サイトのみを根拠とする情報は、確定した事実ではなく推測や参考情報として扱っているか

## コードと再現性

- 構文、型定義、制御フロー、API の呼び出し方が対象バージョンにおいて正しいか
- import、依存関係、環境変数、設定、起動順序など、動作に必要な要素が揃っているか
- コマンドを実行すべき作業ディレクトリが明記されているか
- 記事中の抜粋コードが、実際に動作確認したコードと一致しているか
- 期待される実行結果と実際の観測結果が一致しているか
- 検証日、OS、言語バージョン、主要ライブラリのバージョンを記録しているか
- 構文チェックのみの結果や特定環境での検証結果を、過度に一般化せずその範囲内の事実として提示しているか
- 検証を行っていない挙動や推測にとどまる動作について、未検証である旨を明記しているか
- 同一のコードや設定が複数箇所に記載されている場合、内容に食い違いがないか
- 本文の説明とコードの実装内容が整合しているか

## 設計と読者理解

- 提案・採用している手法が、記事中で提起した課題を実際に解決できているか
- 他の代替案やトレードオフが客観的かつ公平に比較されているか
- 解説上の簡略化が、安全性や実用性を著しく損なわない範囲に収まっているか
- 最小限のサンプルから実践的な実装へとステップアップする過程で、必要な前提概念が漏れなく説明されているか

## リスクと互換性

- 本文、コード、実行結果、画像内の秘密情報や機密情報が、適切にプレースホルダーへ置き換えられているか
- 読者の実行環境やデータに影響を及ぼし得る場合、セキュリティやプライバシーへの配慮・影響について言及されているか
- 不可逆・破壊的な操作に対して適切な警告があり、リソースの後始末手順が明記されているか
- クラウドリソースを作成する記事において、課金発生への注意喚起とリソースの削除手順が記載されているか
- OS、ランタイム、ブラウザ、ライブラリなどの互換性に関する記述が正確か
- 特定環境（OS やアーキテクチャ等）への依存がある場合、読者に明確に伝わる形で記載されているか
- 実験的 API や不安定な依存関係を利用している場合、記事の早い段階でその旨が明示されているか
- 処理の失敗条件、エラー時の復旧手順、運用上の制約事項について説明されているか
