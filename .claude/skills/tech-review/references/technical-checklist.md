# 技術記事の技術レビューチェックリスト

該当する項目だけを適用し、影響の大きい問題を優先する。目的は網羅より影響の大きさとする。

## 主張と根拠

- 中心的な事実が一次情報または記録された観測で裏付けられている
- バージョン依存の情報を現在の資料で確認している
- 仕様と公式文書を文脈どおりに説明している
- 「〜できない」「〜は存在しない」という主張を、一次情報で実際に確認している
- 貼られたリンクが、その近くの主張を実際に裏付けている
- 引用が原典と一致し、文脈を保ったまま提示されている
- 設計理由の記述が、資料で確認できた範囲に収まっている
- 事実、観測、推論、意見を区別している
- 個人ブログや Q&A サイトのみを根拠とする主張を、推測として提示している

## コードと再現性

- 構文、型、制御フロー、API の使い方が対象バージョンで正しい
- import、依存関係、環境変数、設定、起動順序が揃っている
- コマンドを実行するディレクトリを明記している
- 記事の抜粋が、実際に動いているコードと一致している
- 期待結果と観測結果が一致している
- 検証日、OS、言語バージョン、ライブラリバージョンを記録している
- 構文検査や単一環境の結果を、その範囲の結論として提示している
- 未検証の挙動をその旨とともに明示している
- 同じコードが複数箇所にある場合、内容が一致している
- 本文の説明とコードの中身が一致している

## 設計と読者理解

- 採用した方法が、記事で述べた問題を実際に解決している
- 代替案とトレードオフを公平に扱っている
- 教育上の簡略化が、安全で有効な範囲に収まっている
- 最小例から実用例へ進む過程で、必要な概念をすべて示している

## リスクと互換性

- 本文・コード・出力例・スクリーンショットの機密情報がプレースホルダになっている
- 読者の環境や利用者のデータに影響する場合、セキュリティとプライバシーへの影響を扱っている
- 破壊的な操作に警告があり、後始末の手順が書かれている
- クラウドリソースを作る記事に、課金の発生と削除方法が書かれている
- OS、ランタイム、ブラウザ、ライブラリの互換性が正しい
- 特定環境への依存が、そうと分かる形で書かれている
- 実験的な API と不安定な依存関係を記事の早い段階で示している
- 失敗条件、復旧方法、運用上の制約を説明している
