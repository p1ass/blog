# p1ass の文体

文体は題材を問わず統一する。技術解説、参戦記、雑記のいずれにおいても日本語の語調や表記スタイルをそろえる。

## 基本

- **ですます調**。一人称は「私」を用いる
- **書き言葉に統一する**。口語表現や絵文字は避ける
  - 避ける対象: 絵文字全般、「〜だな〜」「〜しちゃう」「わいわい」「やばい」「ありがたや」、副詞的な「すごい」など
  - 過去記事には口語表現が多く見られ、絵文字も 77 記事中 29 記事で使用されているが、今後は書き言葉に統一する
- 半角英数と日本語の間に半角スペースを入れる
  - 良い例: `Claude Code Action を使って PR の Code Suggestion をしてもらう`
  - 悪い例: `Claude Code Actionを使ってPRのCode Suggestionをしてもらう`
  - 句読点の前後はスペースを空けずに詰める。一方、インラインコードの前後には半角スペースを入れる

## 改行

- 判断基準は「スマートフォンで閲覧した際に、文字が密集して読みにくくなっていないか」とする
- 長文がだらだらと続くのを避け、適度に改行を入れる。ただし、1 文の途中で改行してはならない
- 段落の切れ目には空行を入れる
- 短い文が続く箇所では、2〜3 文を 1 行にまとめてよい

## 表現

- `**太字**` による強調は真に重要な要所のみに絞り、1 つの記事で数か所程度にとどめる
- 強調の対象は、流し読みする読者にも確実に届けたい結論や、意外性のある事実とする
- 強調は見出しではなく本文中で使い、見出し自体を太字などで装飾しない
- 文脈から主語が明らかな場合は「私は」を省略する
- **肯定形で書く**。同じ内容を肯定形で表現できる場合は、そちらを選択する
  - 「テンプレートに囚われない」→「題材に合う流れを優先する」
  - 「〜してはいけない」→「〜を避ける」「〜の対象外とする」
  - 「数字をぼかさない」→「数字をそのまま出す」

## 見出し

- **見出しは名詞句か短い文 1 つで完結させる**。ダッシュやハイフンでサブタイトルを付け足さない
  - 良い例: `## 残すもの`、`## Hono を採用した理由`、`### ポイント`
  - 悪い例: `## 残すもの — 口語をやめても、これは削らない`
- 補足事項は見出しに含めず、直後の本文に記述する
- 締めの見出しは `## おわりに` で統一する

## 機械的に見える書き方

textlint の `@textlint-ja/preset-ai-writing` で検出されるような、AI 特有の機械的な表現を避ける。執筆時にも意識する。

- `- **項目**: 説明` のような画一的な箇条書きを避け、`- 項目は〜` と自然な地の文で書く
- 「注意」「ポイント」などの語を太字にして行頭に置くのを避け、自然な文の流れの中で説明する
- コロンでコードブロックや箇条書きを導入する英語風の構文を避ける (`次の通りです:` → `次の通りです。`)
- 絵文字を箇条書きの先頭に置かない

## 避ける表現

- 誇張表現 (`圧倒的に`、`劇的に`、`革命的な` など)
- 理由を示さずに言い切る文 (根拠のない「〜べきです」)
- 中身のない前置き (「〜について説明したいと思います」→「〜を説明します」)
- 同一の文末表現の 3 連続 (例: 「〜ます。〜ます。〜ます。」)
- 冗長な言い回し (`〜することができます` → `〜できます`)
- `〜のは、〜です` のような強調構文による文の接続。主語と述語をストレートに結ぶ
  - `押さえておきたいのは、モデル自身は Tool を実行しないことです` → `モデル自身は Tool を実行しません`
  - `2 つを分けているのは、道筋を決めるのがコードか LLM かという点です` → `Workflow と Agent の違いは、道筋をコードと LLM のどちらが決めるかにあります`
